# 01 总览与验收标准

## 产品定义

NDirty 是离线 Windows 软件，不是“自动去水印器”。用户导入一张图像后，可让软件提出文字/异常区域候选，也可自行绘制蒙版；NDirty 使用本地修补模型在蒙版区域生成内容，用户比较效果、局部重试并导出结果。

效果优先规则：所有修补引擎必须在原图分辨率坐标系中工作；对固定尺寸模型，应以蒙版为中心提取保比例的方形上下文区域、使用反射补边、完成后只合成用户确认的蒙版像素。禁止将任意比例整图直接拉伸为模型方形输入。

## 用户主链路

```text
启动 EXE → 打开图像 → 自动候选（可跳过）→ 编辑蒙版
→ 选择模型与质量 → 本地补全 → 滑杆/并排预览
→ 可撤销、局部重试 → 另存为 PNG/JPEG
```

## MVP 功能清单（必须）

1. 打开 PNG、JPG/JPEG、WEBP、BMP；不改写原图。
2. 画布支持缩放、平移、适配窗口、棋盘透明背景和图像元信息提示。
3. 蒙版编辑：画笔、橡皮、矩形选区、套索选区、撤销/重做、笔刷大小/硬度。
4. 一键修补：使用本地 LaMa ONNX 权重；无网络、无 API Key。
5. 预览：原图/结果切换、并排、滑杆对比；修补前原图和蒙版必须可见。
6. 导出：PNG/JPEG，文件名默认追加 `_ndirty`；可选择质量和输出位置。
7. 健壮性：不支持格式、超大图、模型缺失、推理失败、磁盘不足都要给出可理解的提示；原图和项目数据不得损坏。
8. 合规文案：首次运行或导出前提醒“仅处理您拥有权利或已获授权的图像”。

## 进阶功能（P4 后）

- OCR 检测文字，用户一键转为蒙版；不要自动选择所有文字。
- 交互式智能分割：优先 SAM 点选/框选；在 P4 可采用本地 GrabCut 框选生成蒙版候选。
- 模型可选：LaMa（默认）、ZITS（线条结构）、SDXL Inpaint（复杂语义）。仅在总体积预算允许时打包；首发不包含 SDXL。
- 重新生成只作用于当前蒙版，不修改源文件。

## 不做的内容

- 不训练基础图像生成模型；训练成本、数据版权、体积和交付风险均不适合首版。
- 不保证人脸、证件文字、品牌标识或被大面积遮挡对象的真实性。
- 不以“移除第三方版权标识”为产品卖点。

## 验收样例与质量定义

建立 `tests/assets/` 下的自有或可再分发样例：纯色墙面文字遮挡、草地/纹理污渍、直线建筑物遮挡、照片边角污渍、错误输入。每例配有预期蒙版 PNG。

| 检查项 | 通过标准 |
|---|---|
| 离线 | 断网后启动、打开、推理、导出全流程成功 |
| 原图保护 | 输入文件 SHA-256 在操作前后不变 |
| 蒙版 | 编辑后的 PNG 与画布显示一致，白色=修补、黑色=保留 |
| 性能 | 1024px 长边样例在推荐 GPU 下可完成；CPU 可完成且 UI 不假死 |
| 可恢复 | 失败后可继续编辑/重试，不丢失当前项目 |
| 打包 | 在未安装 Python 的干净 Windows 虚拟机中可启动 |
| 体积 | 发布包、模型、运行时、文档之和小于 10 GB，并留出至少 10% 余量 |

## 关键决策

- GUI：PySide6；图像数组：Pillow + NumPy + OpenCV；推理：onnxruntime。
- 首版模型：OpenCV 发布的 LaMa ONNX，Apache-2.0；优先 CPU/GPU provider 自动降级。
- 项目文件：`.ndirty` 实为 ZIP（`project.json`、`mask.png`、操作元数据），不嵌入原图，避免项目膨胀。
