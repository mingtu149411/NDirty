# 02 技术架构与体积预算

## 架构

```text
GUI（PySide6）
 ├─ 工作区/画布：缩放、平移、叠加蒙版、历史记录
 ├─ 应用服务：打开、保存项目、导出、任务状态
 ├─ 检测服务：OCR/交互式分割（SAM 或 GrabCut，仅作为候选蒙版来源）
 ├─ 修补服务：统一 InpaintEngine 接口
 │   ├─ LamaOnnxEngine（P3 必做）
 │   ├─ ZitsEngine（P4 可选）
 │   └─ DiffusionEngine（仅插件化接口，默认不打包）
 └─ 基础设施：日志、配置、模型定位、依赖/版本诊断
```

所有推理在工作线程执行。UI 线程仅刷新进度，允许取消尚未提交的任务；取消后不写出结果文件。

## 推荐目录

```text
NDirty/
  src/ndirty/{app,ui,domain,services,engines,infra}/
  tests/{unit,integration,assets}/
  models/{lama,ocr,sam}/
  vendor/{python,ffmpeg_if_needed}/
  scripts/{bootstrap,download_models,build,check_size,smoke_test}.ps1
  docs/{用户指南,第三方许可证}/
  build/                  # 忽略版本控制
  dist/                   # 忽略版本控制
  项目规划/
  pyproject.toml
  requirements.lock
  README.md
  THIRD_PARTY_NOTICES.md
```

模型不得散落在用户缓存目录；运行时使用相对 `models/` 路径。模型下载脚本只供开发阶段使用，发行版随包附带经过校验的权重。

## 体积上限（10 GB）

| 组成 | 首发预算 | 原因 |
|---|---:|---|
| LaMa ONNX 权重 | ≤0.25 GB | MVP 必需 |
| OCR 与可选交互分割权重 | ≤1.8 GB | 优先轻量变体；GrabCut 无额外权重；可延迟到 P4 |
| Python + PySide6 + CPU ONNX 运行时 | ≤1.5 GB | 通过干净环境构建后实测 |
| 应用、测试、文档、日志模板 | ≤0.5 GB | 保持轻量 |
| 构建/安装冗余 | ≤1.0 GB | 仅发行包计入交付清单 |
| 保留容量 | ≥5 GB | 禁止首发捆绑 SDXL 等数 GB 权重 |

以实际 `check_size.ps1` 的字节数为准，不以估算替代检查。开发虚拟环境、缓存和中间模型不应放入最终发布目录。

## 模型策略与许可证记录

- LaMa：默认离线修补；记录下载来源、哈希、许可证和版本。
- LaMa 质量管线：根据蒙版 bbox 提取带上下文的保比例方形 ROI，以反射补边缩放至模型输入；输出反变换后仅合成蒙版区域。小遮挡不得因整图缩放丢失细节。
- OCR：仅在 P4 引入，须验证中文/英文识别和离线权重许可。
- 交互分割：仅作为“点选/框选辅助”，不可替代用户确认；优先小型 SAM，或使用无需额外权重的 GrabCut。
- 扩散模型：不纳入首发包，除非重新审查许可证、显存要求、离线权重体积和安全提示。

每个新增模型必须在同一固定样例集上与当前 LaMa 质量管线比较，不能仅以模型名称或单张成功案例替换默认引擎。

`第三方清单.md` 必须逐项包含名称、版本、来源 URL、许可证、SHA-256、是否纳入发行包和体积。

## 安全与隐私

- 默认禁用网络请求；启动时不做遥测、更新检查或模型下载。
- 日志不记录完整图片路径之外的图片内容；默认不上传图片。
- 所有临时文件写入应用专用临时目录，成功后删除；异常退出时下次启动可清理。
- 导出必须另存，禁止覆盖原图作为默认行为。
