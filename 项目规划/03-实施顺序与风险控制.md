# 03 实施顺序与风险控制

## P0：工程基线

建立可重复的 Python 环境、代码规范、锁文件、单元测试和 Git 忽略规则。首先验证一个最小 PySide6 窗口能在目标 Windows 系统启动。此阶段不引入任何大模型。

## P1：工作台

实现 `Document`（原图、显示缩放、蒙版、结果图、dirty 状态）和纯 UI 画布。先用合成色块验证坐标映射，再接图片。画布坐标一律存储为原始图像像素坐标，禁止把屏幕坐标直接写入蒙版。

## P2：蒙版编辑

蒙版为单通道 `uint8` PNG：0 为保持、255 为需补全。使用命令模式历史记录：每次笔划保存差异块，避免对大图重复复制整张图。矩形、套索及画笔最终都输出同一个蒙版。

## P3：MVP 推理与导出

定义 `InpaintEngine.inpaint(image, mask, options) -> Image`，再实现 LaMa ONNX。模型输入尺寸、保比例 ROI、反射补边、归一化和输出裁剪必须封装在 engine 内并用单元测试固定；不得将整张非方形图像强拉伸为 512×512。先验证无 GUI 的命令行烟雾测试，再接 UI。导出在成功写到临时文件后才原子性移动到目标路径。

## P4：智能候选区

先接 OCR：它只返回文本框列表，用户点击“加入蒙版”才合并。之后接交互分割：SAM 或 GrabCut 框选返回预览蒙版，用户确认后合并。候选层永远不能直接触发修补。

## P5：体验、离线和稳定性

增加任务取消、模型缺失诊断、CPU/GPU provider 回退、项目保存、错误对话框和清理机制。切断网络进行完整回归。测试中文路径、含空格路径、超大图和损坏图片。

## P6：打包交付

在全新 Windows 虚拟机上构建并测试 PyInstaller 包，确认不需 Python。发行目录只保留必要 DLL、运行时和模型。生成 SHA-256、许可证文件、用户指南、版本号与更新记录。

## 风险表

| 风险 | 应对 |
|---|---|
| 修补结果不可信 | UI 明示“生成补全”；允许缩小蒙版、多次局部重试和原图对比 |
| 大图内存溢出 | 限制可打开像素数；分块预览；推理前显示预计内存并要求确认 |
| ONNX provider 不兼容 | CPU 必须作为基线；CUDA 为可选并在诊断页说明 |
| 打包缺 DLL | 在干净虚拟机执行烟雾测试，禁止只在开发机验收 |
| 超过 10 GB | 每个阶段执行体积脚本；SDXL 仅作为外置可选模型，不随首发包 |
| 误检文字/正常物体 | 只展示候选，不做自动提交；保留撤销和可视化蒙版 |
