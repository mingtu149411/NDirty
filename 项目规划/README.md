# NDirty 制作规划索引

目标：制作一款名为 **NDirty** 的 Windows 本地图像遮挡补全软件。它接收单张本地图像，辅助用户建立“遮挡物蒙版”，调用本地模型补全蒙版区域，提供前后预览与导出。软件完全离线运行，最终交付 EXE；项目（源码、Python 运行时、模型、依赖、构建产物）总量不得超过 **10 GB**。

## 最高优先级：补全效果

在合法、离线与 10 GB 约束内，视觉补全效果优先于开发速度、模型体积最小化和功能数量。实现不得把原始画面非等比拉伸后直接推理；必须保持原图像素坐标、围绕蒙版保留足够上下文、仅替换用户确认的蒙版区域，并在真实模型与固定样例上回归验证。

## 先读这里

1. 先执行 `01-总览与验收标准.md`，确认产品边界和可交付定义。
2. 按 `02-技术架构与体积预算.md` 的技术栈和目录结构建立工程，禁止在未记录体积预算的情况下加入大模型。
3. 依次将 `提示词/` 中的提示词交给 Codex 执行。每次只执行一个提示词，完成验收后再进入下一步。
4. 每次模型、依赖或构建产物变动后，更新 `NDirty/项目状态.md` 与 `NDirty/第三方清单.md`，并执行体积检查。

## 非目标与合规边界

- 不承诺恢复被遮挡区域的真实原始像素；系统只生成与周边一致的合理内容。
- 首版不做在线视频、批量队列、云端 API、账户系统、图像超分辨率或训练新基础模型。
- 仅处理用户拥有权利或已获授权的本地图片。界面与文档须说明这一点。
- 首版的“自动识别”是候选建议，不自动覆盖用户选择；最终蒙版始终由用户确认。

## 设备基线

- 支持：Windows 10/11 x64；默认 CPU 可运行。
- 推荐：NVIDIA GPU（CUDA）可显著提升推理速度；GPU 属于可选加速，不能成为软件启动前提。
- 运行时：内嵌 Python，不依赖用户预装 Python、网络或云端服务。

详细规划在本目录文档与 `提示词` 文件夹中。P7 仅在 `04-训练与特化策略.md` 的启动门槛全部满足后执行，不能影响正式版 EXE 的 P6 交付。
