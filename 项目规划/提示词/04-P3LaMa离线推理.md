# Codex 提示词：P3 LaMa 离线补全 MVP

在 NDirty P2 的基础上，只实现离线 LaMa 推理和结果预览。请先阅读当前第三方清单和体积预算。

效果优先约束：不得把任意比例整图直接拉伸至 512×512。应以蒙版 bbox 为中心提取约 3 倍遮挡跨度的方形原分辨率上下文（最小 128px），越界图像反射补边、越界蒙版补黑，缩放至模型输入；输出恢复至 ROI 后只能合成用户确认蒙版内的像素。结果视图必须隐藏红色编辑蒙版。

要求：
1. 定义稳定的 `InpaintEngine` 抽象接口，输入为 RGB 原图、单通道蒙版、选项；输出 RGB 结果及可展示的错误。UI 不得直接处理 ONNX 张量。
2. 以 LaMa ONNX 实现 `LamaOnnxEngine`；模型须位于 `models/lama/` 并从相对应用路径定位。记录权重来源、版本、许可证、SHA-256、大小。
3. 引入 `onnxruntime` CPU provider。若后续支持 CUDA，必须是可选 provider 并可回退 CPU；不要因 GPU 不可用而退出。
4. 完整封装预处理：RGB 转换、保比例 ROI、反射补边、蒙版二值化、归一化、输出反变换和裁剪。补边区域不可出现在最终结果；为小遮挡保留尽可能多的有效像素。
5. 推理运行在工作线程，界面提供进度、禁用重复提交、可取消；取消或失败不得覆盖当前结果。
6. 增加结果模式：原图、结果、并排、可拖动滑杆对比；结果/叠加模式不得覆盖红色蒙版，允许从当前蒙版再次推理。
7. 导出 PNG/JPEG，默认新文件名 `_ndirty`，通过临时文件成功写入后再移动到目标；默认不覆盖原图。
8. 增加无 GUI 烟雾测试、预处理/裁剪单元测试和至少一张自有样例端到端测试。断网后再次运行此测试。

验收：模型存在时完成端到端补全；模型缺失时显示安装/诊断路径但不尝试联网下载；记录耗时、峰值内存（如能测）和发行目录总大小。不得加入 OCR、SAM 或扩散模型。
